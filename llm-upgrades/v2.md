# llm-upgrades v2 — merge `meta.json` + `fix-meta.json` into `settings.json`

Applies to a repo currently at checkpoint `0` — the implicit checkpoint of every repo bootstrapped
before `schema_version` existed at all (2 separate files, `notebooks/review/<repo>/meta.json` for
`review.md` and `notebooks/review/<repo>/fix-meta.json` for `fix.md`, with `chat_language`
independently duplicated in both — the exact dual-write bug-class fixed as a one-off patch in PR
#19, made structurally impossible by this migration instead). Targets `schema_version: 2`. There is
no `v1.md` — version numbers here track the plugin's config `schema_version` values that actually
need a migration (see `llm-upgrades/index.md`), not a sequential migration count; this is simply the
first `schema_version` bump the plugin has ever needed.

## RENAMED

- `notebooks/review/<repo>/meta.json` + `notebooks/review/<repo>/fix-meta.json` → single
  `notebooks/review/<repo>/settings.json`, restructured into 3 top-level nodes: `shared`, `review`,
  `fix`.

## ADDED

- Top-level `schema_version` (number) — did not exist before this migration. Set to `2`.
- `shared` node, holding `chat_language` — the ONE place this field lives from now on (previously
  it existed independently inside both old files).

## MODIFIED

- Every field of the old `meta.json` EXCEPT `chat_language` (`bootstrapped`, `doctored`,
  `doctored_at`, `doctor_schedule`, `project_docs_found`, `templates_copied`,
  `auto_submit_review`, `auto_resolve_fixed_findings`, `pr_template_paths`, `review_ci_status`,
  `many_files_threshold`, `big_file_threshold_kb`, `_comments`) — name and value UNCHANGED, moved
  as-is under the new `review` node.
- Every field of the old `fix-meta.json` EXCEPT `chat_language` (`decline_needs_confirmation`,
  `auto_push`) — name and value UNCHANGED, moved as-is under the new `fix` node.

## REMOVED

- `notebooks/review/<repo>/meta.json` and `notebooks/review/<repo>/fix-meta.json` themselves, once
  their content has been merged into `settings.json`.

## Migration steps

Literal instructions for whoever applies this (today: `/open-pr:update-plugin` Step 4 — follow
these exactly, do not improvise a different shape):

1. `Read` `notebooks/review/<repo>/meta.json` if it exists (else treat as `{}`); `Read`
   `notebooks/review/<repo>/fix-meta.json` if it exists (else treat as `{}`). Neither exists →
   nothing to migrate (this repo has never bootstrapped either command) — just write
   `{"schema_version": 2}` with no `shared`/`review`/`fix` node, done, skip the rest of this list.
2. Pick `chat_language`: prefer `meta.json.chat_language` if present, else
   `fix-meta.json.chat_language` if present, else omit the `shared` node entirely (repo never
   detected it yet). Both files have a value AND they disagree (the exact bug-class this migration
   removes) → prefer `meta.json`'s value (the one `review.md` last showed in chat — reviews run
   more often than fixes) and mention this choice, plainly, in `/open-pr:update-plugin` Step 5's
   summary to the user.
3. Build the `review` node = every key of `meta.json` EXCEPT `chat_language`, unchanged. `meta.json`
   didn't exist → omit the `review` node entirely.
4. Build the `fix` node = every key of `fix-meta.json` EXCEPT `chat_language`, unchanged.
   `fix-meta.json` didn't exist → omit the `fix` node entirely.
5. `Write` `notebooks/review/<repo>/settings.json`:
   ```json
   {
     "schema_version": 2,
     "shared": { "chat_language": "<value from step 2>" },
     "review": { "...": "as built at step 3" },
     "fix": { "...": "as built at step 4" }
   }
   ```
   (Omit `shared`/`review`/`fix` individually per the omission rules in steps 2-4 above.)
6. Delete the 2 old files: remove `notebooks/review/<repo>/meta.json` and
   `notebooks/review/<repo>/fix-meta.json`, whichever existed.
7. Commit into the nested `notebooks/review/.git` repo (the one `src/setup-flow.md` Part A
   initializes) — ONLY if that nested repo already exists (`notebooks/review/.git` present, meaning
   `/open-pr:review` or `/open-pr:fix` has run at least once on this machine before); it not
   existing means there is nothing to commit yet, skip this step entirely, do NOT `git init` it
   yourself here:
   ```bash
   git -C notebooks/review add "<repo>/settings.json"
   git -C notebooks/review rm --cached "<repo>/meta.json" "<repo>/fix-meta.json" 2>/dev/null
   git -C notebooks/review commit -m "chore: migrate <repo> settings to schema_version 2 (settings.json)"
   ```
   (the `rm --cached` call may error harmlessly if one of the 2 old files was never tracked — ignore
   that). Commit identity: reuse the EXACT fallback chain already described in `src/setup-flow.md`
   Part A under "Commit identity" — try `git config user.name`/`user.email` at the main repo's pwd
   first (via `-c user.name="<value>" -c user.email="<value>"` immediately after `-C
   notebooks/review`), only fall back to `-c user.name="review-plugin" -c
   user.email="review-plugin@local"` if neither the project nor global config has any identity at
   all.
