# llm-upgrades v3 — add `shared.git_remote_type` (GitLab support)

Applies to a repo currently at checkpoint `2` (already merged into `settings.json` by
`llm-upgrades/v2.md`). Targets `schema_version: 3`. Triggered by the plugin adding GitLab as a
second supported vendor (`src/vendors/gitlab.md`) — every repo reviewed by this plugin before this
migration existed was reviewed against GitHub, so the default below is a safe assumption for old
data, never a guess.

## ADDED

- `shared.git_remote_type` (string, `"github"` | `"gitlab"`) — did not exist before this migration.
  Every repo migrating through this file gets it set to `"github"` unconditionally (100% of repos
  bootstrapped before this version used the plugin's only vendor at the time).

## Migration steps

Literal instructions for whoever applies this (today: `/open-pr:update-plugin` Step 4 — follow
these exactly, do not improvise a different shape):

1. `Read` `notebooks/review/<repo>/settings.json`. Doesn't exist at all → nothing to migrate (this
   repo has never bootstrapped either command) — skip the rest of this list, no file to write.
2. `shared` node missing entirely → create it holding only `git_remote_type: "github"`. `shared`
   node exists already (e.g. holds `chat_language`) → `Edit` in place, ADD `git_remote_type:
   "github"` alongside it, leave every existing key untouched. `shared.git_remote_type` already
   present (repo already migrated, or bootstrapped post-GitLab-support) → leave as-is, do NOT
   overwrite — this migration is idempotent, never downgrades an already-correct `"gitlab"` value
   back to `"github"`.
3. Set top-level `schema_version` to `3`.
4. Commit into the nested `notebooks/review/.git` repo (the one a fresh bootstrap
   initializes) — ONLY if that nested repo already exists (`notebooks/review/.git` present); it not
   existing means there is nothing to commit yet, skip this step entirely, do NOT `git init` it
   yourself here:
   ```bash
   git -C notebooks/review add "<repo>/settings.json"
   git -C notebooks/review commit -m "chore: migrate <repo> settings to schema_version 3 (git_remote_type)"
   ```
   Commit identity: try `git config user.name`/`user.email` at the main repo's pwd first
   (via `-c user.name="<value>" -c user.email="<value>"` immediately after `-C notebooks/review`),
   only fall back to `-c user.name="review-plugin" -c user.email="review-plugin@local"` if neither
   the project nor global config has any identity at all.
