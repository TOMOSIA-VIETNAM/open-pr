# 评审哪些方面

[← README](../../README.zh-Hans.md)

六个维度。**团队规则永远压过** 这六个。

| # | 标准 | 关注什么 |
| --- | --- | --- |
| 1 | **Bug 与逻辑** | 看得见的逻辑错误、边界情况（空 / null / 边界值）、条件分支和错误路径有没有被处理 |
| 2 | **安全** | 硬编码的密钥、未校验的输入直接进入 query / 命令 / 渲染、敏感操作缺少权限检查 |
| 3 | **性能** | 值得缓存或批处理的重复 API / DB / 计算、把整份大数据集读进内存而不是流式处理 |
| 4 | **代码质量** | 命名不合项目规范、重复代码、一个单元做了太多事、残留的死代码（注释掉的代码块、没用到的 flag / import、指向已删除任务的 TODO） |
| 5 | **可维护性与可读性** | 逻辑不显然处有注释且只陈述当下为真的事（不复述过去）、测试覆盖正常路径与错误路径、设计给下一次改动留出余地 |
| 6 | **框架 / 语言相关** | 按技术栈的模板：Rails、Vue、React、Python、Node.js、Lambda、PHP、Laravel、WordPress、Shell、Makefile，以及作为 AI agent 指令而写的 markdown。技术栈未知 → 当场写出模板 |

> [!IMPORTANT]
> **冲突**时的优先级：团队规则 → 学到的 memory → 该技术栈的模板 → 上面 5 条标准。团队规则永远优先。
